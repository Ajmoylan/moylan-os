# Azure Static Web Apps: deployment readiness

Planning checklist, 16 November 2026 (Portfolio Content 1.0). Nothing here has been created,
configured or deployed: no Azure resources, no DNS changes, no deployment credentials.
Target: **Azure Static Web Apps (Free plan)**, custom domain **moylanos.dev** (DNS at Cloudflare),
deployed by **GitHub Actions** (ARCHITECTURE.md §2 and "Azure Static Web Apps configuration").

## 1. Compatibility: ready

- [x] Static output only: React Router 7 with `ssr: false` and `prerender`, so every route is a
      prerendered HTML file that hydrates into an SPA. No runtime server and no API.
- [x] `build/client` is the deployable folder: about 1.8 MB, 62 files (the Free plan allows 250 MB).
- [x] `build/client/staticwebapp.config.json` is generated by `scripts/postbuild.mjs`. It holds the
      CSP with each inline script's hash, and the build fails if it grows past 20 KB (the platform
      limit).

## 2. Build output and routing: ready, one check on the first preview

- [x] `trailingSlash: "never"` gives one canonical URL per page (`/about/` redirects 301 to `/about`).
- [x] There's no `navigationFallback`, because every route is prerendered. Unknown URLs get the designed
      `/404.html` via `responseOverrides`.
- [ ] **Verify on the first preview environment** that SWA keeps the **404 status** when it
      rewrites to `/404.html`. Microsoft's docs don't say; the local emulation
      (`scripts/serve-static.mjs`) does.
- [x] Hashed assets live under `/assets/` (`Cache-Control: public, max-age=31536000, immutable`);
      HTML is `no-cache`.

## 3. GitHub Actions: workflow not yet added (Phase 6, needs approval)

- [x] CI already gates every PR: audit, format, lint, typecheck, unit, production build with all
      guards, Chromium e2e with axe, a flagged morph build with its required tests, CodeQL and
      dependency review.
- [ ] Add a deploy workflow using `Azure/static-web-apps-deploy`, pinned to a full commit SHA like
      every other action:
  - deploy the **already built and guarded** `build/client` (`skip_app_build: true`,
    `app_location: build/client`), so the guarded `npm run build` stays the only build;
  - run on pushes to `main`, behind a protected `production` environment;
  - keep the deployment token as an environment secret (`AZURE_STATIC_WEB_APPS_API_TOKEN`),
    never in the repository;
  - set `permissions` to the minimum (`contents: read`, plus `pull-requests: write` only if PR
    previews are enabled).
- [ ] Decide on PR preview environments. The Free plan includes 3, but their URLs are public:
      only use them for content that may be public.

## 4. Custom domain and HTTPS (Cloudflare DNS): steps planned, none taken

- [ ] Create the Static Web App, then add `moylanos.dev` (apex) and `www.moylanos.dev` as custom
      domains in the portal.
- [ ] Apex domain: validate with the **TXT** record SWA provides. Then point it with a Cloudflare
      **CNAME at the root** (Cloudflare flattens it) to the app's `*.azurestaticapps.net`
      hostname. `www`: a CNAME to the same hostname, and choose which name redirects to the other.
- [ ] Keep these records **DNS only (grey cloud)**, at least during validation and certificate
      issuance. SWA issues and renews free managed TLS certificates itself. Proxying through
      Cloudflare would put a second CDN in front, could change headers or caching, and needs
      "Full (strict)" TLS. Revisit only if there's a need.
- [ ] The HSTS header is `max-age=63072000; includeSubDomains; preload`. Confirm before launch that
      every subdomain of moylanos.dev serves HTTPS (`includeSubDomains`). Only submit the domain to
      the HSTS preload list deliberately, because removal is slow.
- [ ] Email: the site now publishes **alex@moylanos.dev**. Confirm its MX records (and SPF, DKIM
      and DMARC) work, and that a test message arrives, before launch. Changes to those records
      must not touch the web records above.

## 5. Security headers: ready

- [x] Applied by `globalHeaders`: a hash-based CSP (`default-src 'none'`; no `unsafe-inline` or
      `unsafe-eval`), HSTS, `X-Content-Type-Options: nosniff`, Referrer-Policy, Permissions-Policy,
      COOP, CORP and `X-Frame-Options: DENY`.
- [x] Tested end to end against the real headers locally (Playwright and axe), with CSP
      violations failing any test.
- [ ] After the first deployment, check the live headers (for example with securityheaders.com)
      and confirm that `upgrade-insecure-requests` and the CSP are served unmodified.

## 6. Asset optimisation: ready

- [x] Initial JS is 124.9 KB gz against a 125 KB budget (enforced). The 3D stage is lazy, at
      158.2 KB gz (review target 160).
- [x] The portrait is AVIF with a WebP fallback at 480, 768 and 1086 px (10–45 KB AVIF), hashed
      under `/assets/` and requested only by `/about`. Fonts are self-hosted woff2.
- [x] No source maps in production. SWA compresses text responses itself.
- [ ] **Budget review before more content:** about 0.1 KB of initial-JS headroom is left. The
      homepage loads the project and profile data, so the next content additions must either
      move data out of the homepage's initial load or come with an explicit budget review.

## 7. Production-only safeguards: ready

- [x] `npm run build` fails on any trace of a local voice preview or placeholder audio, on TEST
      morph shaders without `VITE_MORPH_TEST=1`, and on budget or CSP problems.
- [x] Deploy only `npm run build` output from CI, which has no `.env.local` and no
      `public/audio`. Never deploy `build:morph-test` or `build:voice-preview` output.
- [x] No secrets in `src/` (everything there ships to the browser). Tests check that no private
      phone number or private email appears in site content.
- [ ] Final privacy notice (currently a draft) and the real-device accessibility checklist
      (GitHub issue #25, which includes #20) before the production launch.

## 8. Expected costs

Verify on Azure's pricing page before creating anything; prices change.

- **Azure Static Web Apps Free plan: no charge.** It includes managed TLS, custom domains (two
  per app), 100 GB of bandwidth a month and 3 preview environments. That's enough for this site.
- **Standard plan** (about US$9 per app per month at the time of writing) is only needed for
  an SLA, more custom domains or bandwidth, private endpoints, password-protected previews or
  bring-your-own Functions. None is needed now.
- **No other Azure services:** no storage account (assets ship with the app), no Functions, no
  Log Analytics.
- **GitHub Actions:** free for this public repository. **Cloudflare DNS:** free plan.
- Set an Azure **budget alert** (for example US$1) on the subscription anyway, to catch an
  accidental upgrade.
